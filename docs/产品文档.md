## 1. 项目概述

### 1.1 一句话定位
一款**水墨画风、可本地双击可玩、亦可连云端**的修仙门派经营模拟器：从荒山建观开始，外门杂役营生、内门修士问道，炼丹炼器、游历九州、抵御妖潮，最终送弟子九劫飞升，并揭开本门灭门旧案真相。

### 1.2 已确认的产品决策（终版）
1. **画风**：程序化水墨（Canvas 笔触库预烘焙，无外部素材，§6）。
2. **一周目时长**：20~30 小时，**必须由内容撑起**（§5.2 节拍表 + 反注水红线）。
3. **里程碑顺序**：先经营（P1）后修仙（P2）。
4. **工程形态**：正式项目——多源码文件、git 管理（每期打 tag）、CHANGELOG；经典 `<script>` 按序加载，`file://` 双击可玩，零构建零 npm（前端）。
5. **命名**：《云隐仙踪》，全部名词/文案/数值自创。
6. **天劫玩法**：轻量**蓄力护体 QTE**——每劫若干道天雷，各是一道时机条：在"护体带"内按下则无伤借力，偏出则按偏差扣护体/气血；丹药/法宝/护体阵会加宽容错带。不做弹幕、不做多资源管。
7. **不做单文件打包版**：分享给朋友=拷贝整个游戏文件夹。
8. **前后端分离（P7）**：离线优先——不联网游戏 100% 可玩；连上自建 Node 后端可获账号+云存档+门派参观+排行榜（§7.5）。

### 1.3 平台与硬指标
| 项 | 目标 |
|---|---|
| 运行环境 | 现代 Chrome/Safari/Edge，桌面为主；后端 Node ≥ 20 |
| 帧率 | 60fps（24 弟子 + 80 动物/物品在图） |
| 代码体量 | git 管理，总量 ≤ 2MB；前端零构建零依赖，后端零 npm 运行时依赖 |
| 存档 | localStorage 三槽+自动档+导出 JSON；联网时云同步（LWW） |

## 3. 核心玩法循环

```
┌─ 分钟级（实时沙盒微循环）────────────────────────────┐
│  杂役搬运/建造 → 修士打坐纳气 → 需求满足 → 心境起伏  │
│  → 生产排队(丹/器/符) → 野外妖兽游荡骚扰             │
├─ 小时级（经营中循环，游戏内 10~30 日）────────────────┤
│  破境冲关(丹药+风水局) → 新神通点亮 → 新配方解锁 →   │
│  游历带回资源/声望/情报 → 坊市换稀缺 → 扩建/新弟子    │
├─ 整局级（20~30 小时一周目，游戏内约 4 年）────────────┤
│  妖潮/犯山逐波升级 → 九重天劫 → 飞升传承下一代 →     │
│  旧案五章逐层揭开 → 结局(重开盛世/真相大白/道统断绝)  │
└─────────────────────────────────────────────────────┘
```

失败/终局：门派倾覆（全灭）或三代无人飞升判"道统断绝"；无尽模式可关闭终局。

## 4. 系统详细设计

（v0.1 评审通过的 §4.1~§4.19 机制全部保留；v0.3 唯一改动为 §4.18 天劫玩法简化。）

### 4.1~4.19 要点回顾
时间节拍 20tps；灵韵扩散增量更新；杂役 12/修士 12 上限；六维+灵根+特质；五需求→心境；十一境破境公式（灵根×典品×风水×丹药×心境，失败分档：受创/走火/身陨）；四种修行模式（纳气/冲关/炼体/温养）；夺舍换骨丹；五行生克五作用面；风水局（生扶本命→大吉，含"土生金卧室"配方，观星台前隐藏）；营造蓝图制 80 种；庶务优先级表；四艺（丹道火候条/器道锻打/符道走笔/阵道布阵，各带熟练度 0~10）；五大天地灵植（铃音果/垂云藤/五色莲/赤焰果/赭岩参）蕴养反哺；妖潮 30 日一波；九州游历事件链；缘分（拜师/传功/道侣/仇怨）；犯山斗法（御器+神通，同套数值）；飞升传承；旧案主线。

### 4.18 天劫（v0.3 简化版）
- 渡劫境每 30 日一劫共九劫，劫前 5 日可布置：护体丹（扩容错带）、法宝（偏差减伤）、护体阵（失败一次免伤）、道侣护法（额外一条命）。
- **玩法**：每劫 3~6 道天雷，每道雷一条横向时机条——指针来回扫动，中央"护体带"由准备度决定宽窄；按下即判定：命中带内=无伤借力（下道雷指针更慢），边缘=扣护体，带外=扣气血+画面泼墨震颤。护体或气血任一归零则劫败身陨。
- 难度曲线靠准备度自然分层：准备充分的弟子护体带宽、指针慢，几乎无脑可过；裸渡则九死一生——把"战前经营"作为主要难度轴，操作只占三分。

### 4.20 四时与节气
- 四季各 90 日：**春**（灵植催发×1.2、多雨）、**夏**（雷雨日——渡劫/突破危险+但雷属功法加成、妖兽活跃）、**秋**（收割×1.3、游历吉事加权）、**冬**（灵植休眠、心境易低、妖潮前哨）。
- 12 节气各带一个限定事件（立春·开山收徒潮 / 谷雨·灵雨（全图灵韵+1 持续 5 日）/ 夏至·天火流星（掉陨铁）/ 霜降·妖兽南下 / 冬至·围炉共修（全门心境+）…），节气事件与旧案、恩怨支线互有钩子。

### 4.21 恩怨支线与客卿
- 六大门派各一条**恩怨支线**（3~5 节点）：好感推进触发，完成改写该派对犯山/拍卖/游历的态度。
- **客卿长老**：好感达"盟誓"后对方派驻客卿（自带稀有神通，可传艺不可指挥），每派限一。

## 6. 水墨美术风格指南

### 6.1 结论
程序化水墨**可行，中等难度**：笔触预烘焙 + 少量大 sprite 慢速动效，性能与像素同级；水墨的抽象性降低素材精度要求。

### 6.2 视觉基调
- **底**：宣纸米白（#f4efe3）+ 程序化纸纹（噪声 tile 预渲染）。
- **墨**：五墨阶（焦/浓/重/淡/清），全场景 95% 面积只用墨阶灰；点缀色仅朱砂/花青/赭石三种。
- **构图**：地图边缘留白渐隐入纸色，远景淡墨山影两三层，不满屏堆细节。

### 6.3 渲染管线
1. **笔触库**：启动固定种子烘焙 ~200 个笔触 sprite（中锋线/侧锋扫/点苔/飞白枯笔），离屏 atlas，运行时只取用不重算。
2. **皴法**：山石短线簇（披麻/斧劈意趣），预烘焙 tile。
3. **单位**：墨人——浓墨勾轮廓+淡墨衣袂，境界越高衣袂拖尾越长越淡；妖兽浓墨重笔+朱砂点睛。
4. **动效**：云雾=3~4 团半透明白雾慢速漂移；水面=留白+断续波纹线；剑气=飞白枯笔痕；法术=点缀色墨晕；天劫=泼墨+朱砂电光。
5. **UI**：宣纸卷轴面板+墨线描边+篆刻印章（门派印/声望印）；系统楷体/隶书，不引入字体文件。
6. **可读性**：交互/警示信息一律朱砂或印章框高对比；提供"清晰模式"。

### 6.4 风险与对策
笔触随机性→固定种子烘焙库；墨阶难辨→交互层用点缀色+描边；字体缺失→三级 fallback；动效失控→全部复用笔触库原语。

### 7.2 关键技术决策
- **前端零构建**：经典 `<script>` 按序加载，全局命名空间 `XIANG`；无 npm/bundler。
- **模拟渲染解耦**：20tps 固定步长 + rAF 插值；同步 `Tick.pump(n)` 支持测试与跳时。
- **寻路**：A*+JPS+路径缓存。
- **RNG 种子化**：存档带种子可复现；地图由种子重建。
- **git**：每期一次提交并打 tag（`p0`、`p1`…），CHANGELOG 对应。
- **分享**：拷贝整个游戏文件夹（无 node_modules、无数据库文件依赖，双击 index.html 即玩）。

### 7.3 性能预算
| 项 | 预算 |
|---|---|
| 模拟 tick | < 4ms @20tps |
| 渲染帧 | < 8ms（烘焙 sprite，无逐帧笔触计算） |
| 笔触库烘焙 | < 300ms（启动一次） |
| 存档序列化 | < 200ms（异步分片） |

### 7.4 存档（本地）
JSON 快照（版本号+迁移函数），localStorage 三槽+自动档+导入导出；数据集中 `js/db/`。

### 7.5 前后端分离（P7，v0.3 新增）
**原则：离线优先。** 前端完整可玩，`js/net/client.js` 探测到后端才启用云端能力，断网/未登录全功能降级为纯本地。
- **后端**：Node ≥ 20 原生 `node:http` + `node:sqlite`，**零 npm 运行时依赖**（与前端哲学一致）；同仓库 `server/`，`node server/server.js` 一句启动（同时托管静态文件，作为联网开发模式）。
- **API 面**：
  - `POST /api/auth`——设备码+昵称轻账号（不做密码体系，个人自用/朋友间共享够了）
  - `GET/PUT /api/saves/:slot`——云存档三槽，时间戳 LWW（last-write-wins）+设备名标记
  - `POST /api/sects` / `GET /api/sects`——门派快照上传与"参观"（只读浏览他派布局与风水局）
  - `GET /api/board`——排行榜（最速筑基/最高声望/飞升数）
- **同步策略**：手动"上传/下载"+退出自动上传；冲突弹卡片让玩家选本地或云端。
- **不做**：实时多人、交易市场——经营模拟的乐趣在单机节奏，异步参观/排行已是社交上限。
