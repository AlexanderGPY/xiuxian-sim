## 1. 项目概述

### 1.1 一句话定位
一款**水墨画风、零依赖、双击即玩**的修仙门派经营模拟器：玩家扮演一派掌门，从荒山建观开始，外门杂役营生、内门修士问道，炼丹炼器、游历九州、抵御妖潮，最终送弟子九劫飞升，并揭开本门灭门旧案真相。

### 1.2 已确认的产品决策（v0.2 评审结论）
1. **画风**：程序化水墨（Canvas 生成，无外部素材）。可行性评估见 §6 —— 结论：中等难度，较像素风多约两三成渲染管线工作量，与修仙题材高度契合。
2. **一周目时长**：20~30 小时。**原则：时长必须由内容撑起**——每一小时都有新系统/新剧情/新追求解锁（§5.2 节拍表），严禁用数值梯度拉长（如同配方反复刷）。
3. **里程碑顺序**：先经营（P1 荒山立足）后修仙（P2 仙路初启）。
4. **工程形态**：正式项目结构——多源码文件 + git 版本管理 + 文档/测试目录；仍零依赖、`file://` 双击可玩（§7）。
5. **命名**：《云隐仙踪》，全部名词自创（§2 术语映射），不复用原作任何素材/文案/数值。

### 1.3 平台与硬指标
| 项 | 目标 |
|---|---|
| 运行环境 | 现代 Chrome/Safari/Edge，桌面为主，鼠标键盘 |
| 帧率 | 60fps（24 弟子 + 80 动物/物品在图） |
| 代码体量 | 无单文件限制（git 管理），总量控制在 2MB 内；预留"绿色单文件版"打包脚本用于分享 |
| 存档 | localStorage 三槽 + 自动档（每游戏日）+ 导出/导入 JSON |

## 3. 核心玩法循环

```
┌─ 分钟级（实时沙盒微循环）────────────────────────────┐
│  杂役搬运/建造 → 修士打坐纳气 → 需求满足 → 心境起伏  │
│  → 生产排队(丹/器/符) → 野外妖兽游荡骚扰             │
├─ 小时级（经营中循环，游戏内 10~30 日）────────────────┤
│  破境冲关(丹药+风水局) → 新神通点亮 → 新配方解锁 →   │
│  游历带回资源/声望/情报 → 坊市换稀缺 → 扩建/新弟子    │
├─ 整局级（20~30 小时一周目，游戏内约 4 年）────────────┤
│  妖潮/犯山逐波升级 → 九重天劫 → 飞升传承下一代 →     │
│  旧案五章逐层揭开 → 结局(重开盛世/真相大白/道统断绝)  │
└─────────────────────────────────────────────────────┘
```

失败/终局：门派倾覆（全灭）或三代无人飞升判"道统断绝"；无尽模式可关闭终局。

## 6. 水墨美术风格指南（v0.2 新增）

### 6.1 结论先行
**可行，中等难度。** 相比像素风，多出的工作量在"笔触库 + 雾水动画"两块（估计 +20~30% 渲染管线成本，计入 P0/P1）；换来的是题材契合度极高的辨识度。水墨的抽象性反而**降低**了素材精度要求——"意到笔不到"是合法表现。

### 6.2 视觉基调
- **底**：宣纸米白（#f4efe3）+ 程序化纸纹（噪声 tile，一次性预渲染）。
- **墨**：五墨阶——焦/浓/重/淡/清，全场景 95% 面积只用墨阶灰；**点缀色仅三种**：朱砂（印章/警示/重点交互）、花青（水系法术）、赭石（土系/建筑辅助）。色不过三，是水墨可读性的底线。
- **构图**：地图边缘留白渐隐入纸色（"计白当黑"），远景淡墨山影两三层，不做满屏细节。

### 6.3 程序化水墨渲染管线
1. **笔触库（核心资产，P0 交付）**：启动时以固定种子生成 ~200 个烘焙笔触 sprite（中锋线/侧锋扫/点苔/飞白枯笔），存离屏 atlas。生成法：基线多边形 → 边缘 jitter 毛糙 → 尖锋收笔锥化 → 2~3 层半透明浓淡叠加。**运行时只取用不重算**，性能与像素 sprite 同级。
2. **皴法**：山石/岩壁用短线簇模拟披麻皴/斧劈皴（同样预烘焙成 tile）。
3. **单位**：弟子为简约墨人——浓墨勾勒轮廓、衣袂用淡墨笔触，境界越高衣袂拖尾越长越淡（"仙气"可视化）；妖兽浓墨重笔+朱砂点睛。
4. **动效**：云雾=3~4 团大尺寸半透明白雾缓慢漂移；水面=留白+断续波纹线（笔触库复用）；战斗剑气=飞白枯笔痕拖尾；法术=对应点缀色墨晕绽放；天劫=泼墨浓黑+朱砂电光。所有动效用少量大 sprite 慢速移动，帧成本可控。
5. **UI**：宣纸卷轴面板 + 墨线描边 + 篆刻印章元素（门派印=Logo、声望印=等级章）；字体用系统楷体/隶书（macOS 自带 Kaiti SC / STKaiti，跨平台 fallback serif），不引入字体文件。
6. **可读性保障**：所有可交互/警示信息用朱砂色或印章框高对比标注；提供"清晰模式"开关（叠加视图下减少墨色层次、加描边）。

### 6.4 风险与对策
| 风险 | 对策 |
|---|---|
| 笔触随机性导致画面脏乱 | 固定种子烘焙库，人工调优入库；运行时禁逐帧随机 |
| 墨阶灰层次导致信息难辨 | 交互层永远用点缀色；风水/五行视图用印章+描边符号而非纯色块 |
| 楷体跨平台缺失 | font stack 三级 fallback + 自绘标题字（笔触库拼字）仅用于 Logo |
| 动画工作量失控 | 雾/水/拖尾全部复用笔触库与渐变，不新增绘制原语 |

```
├── js/
│   ├── core/             # boot.js tick.js rng.js save.js debug.js(__G) bus.js
│   ├── db/               # 静态数据：realms.js scriptures.js pills.js buildings.js
│   │                     #        items.js beasts.js places.js events.js story.js seasons.js

```

### 7.2 关键技术决策
- **零构建**：经典 `<script>` 标签按序加载（file:// 下无 CORS 问题），全局单命名空间 `XIANG`；不上 npm/bundler，保持"克隆即玩"。
- **模拟渲染解耦**：20tps 固定步长 + rAF 插值渲染；暂停可渲染。
- **寻路**：A*+JPS，路径缓存，<1ms/次。
- **RNG 种子化**：存档带种子，事件可复现。
- **git 版本管理**：每期交付一次提交并打 tag（`p0`、`p1`…）；CHANGELOG 对应。
- **绿色单文件版**（可选，P2 后提供）：打包脚本把 js/ 内联回单 HTML 便于分享，平时开发不依赖它。

### 7.3 性能预算
| 项 | 预算 |
|---|---|
| 模拟 tick | < 4ms @20tps |
| 渲染帧 | < 8ms（含水墨层，烘焙 sprite 无逐帧笔触计算） |
| 存档序列化 | < 200ms（异步分片） |
| 首屏可玩 | < 3s（含笔触库烘焙 <300ms） |

### 7.4 存档
JSON 快照（版本号+迁移函数），localStorage 三槽+自动档+导入导出；数据全集中在 `js/db/`，改数值即改文件。
